# מערכת ניהול ארנק כיתתי עם חנות 🏪

מערכת מלאה לניהול נקודות תלמידים וחנות כיתתית עם מערכת אישורים.

## תכונות המערכת

### למורים 👨‍🏫
- **ניהול תלמידים**: הוספה, עדכון יתרות, מעקב אחר כל התלמידים
- **ניהול חנות**: הוספת מוצרים, מחיקת מוצרים, קביעת מחירים
- **מערכת אישורים**: קבלת התראות על בקשות קנייה, אישור/דחיית קניות
- **היסטוריה מלאה**: צפייה בכל הקניות של כל התלמידים
- **הוספת מורים נוספים**: יכולת ליצור חשבונות מורה נוספים

### לתלמידים 👨‍🎓
- **ארנק דיגיטלי**: צפייה ביתרה האישית בממשק מעוצב
- **חנות אינטראקטיבית**: רכישת מוצרים מהחנות הכיתתית
- **מעקב קניות**: צפייה בהיסטוריית הקניות ובסטטוס האישורים
- **התראות**: מעודכנים על סטטוס הקנייה (ממתין/אושר/נדחה)

## התקנה והפעלה

### דרישות מקדימות
- Node.js מותקן במחשב
- חשבון MongoDB (MongoDB Atlas - חינם)

### שלבי התקנה

1. **התקנת חבילות**
```bash
npm install
```

2. **הגדרת משתני סביבה**

העתק את `.env.example` ל-`.env` ומלא את הערכים. שלושה מהם חובה, והשרת מסרב לעלות בלעדיהם:

| משתנה | מה זה |
|---|---|
| `MONGO_URI` | חיבור למסד הנתונים |
| `JWT_SECRET` | מפתח לחתימת עוגיית הסשן. אקראי, 32 תווים לפחות |
| `SUPERADMIN_1_NAME` + `SUPERADMIN_1_PASSWORD_HASH` | מנהל-על ראשון |

יצירת `JWT_SECRET`:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

יצירת hash לסיסמת מנהל-על:
```bash
npm run hash -- "הסיסמה שלך"
```

3. **הפעלת השרת**
```bash
npm start
```

4. **גישה למערכת**
פתח דפדפן וגש ל: `http://localhost:3000`

### הרצה מקומית בלי מסד נתונים אמיתי

```bash
node scripts/dev-server.js
```
מרים מונגו זמני בזיכרון עם נתוני דמו על פורט 4321. לא נוגע בשום מסד נתונים אמיתי.

### בדיקת אבטחה

```bash
node scripts/security-smoke-test.js
```
63 בדיקות שמוודאות שאי אפשר לגשת ל-API בלי התחברות, שמורה לא יכול לגעת בכיתה אחרת, שתלמיד לא יכול לשנות לעצמו נקודות, ושקישורי ההרשמה נועלים במכסה ומפסיקים לעבוד אחרי מחיקה.

## הוראות שימוש

### התחברות
כולם נכנסים דרך אותו מסך עם קוד אישי אחד:
- **מנהל-על**: הסיסמה שהוגדרה ב-`SUPERADMIN_1_PASSWORD_HASH`
- **מורה**: סיסמת המורה שמנהל-העל קבע בעת יצירת הכיתה
- **תלמיד**: קוד התלמיד שהמורה הזין

הקודים חייבים להיות ייחודיים בכל המערכת, כי מסך ההתחברות מזהה את המשתמש לפי הקוד בלבד.

### יצירת כיתות (מנהל-על בלבד)
1. היכנס כמנהל-על
2. מלא שם כיתה, שם מורה וסיסמת מורה (8 תווים לפחות)
3. מסור את הסיסמה למורה — היא נשמרת מוצפנת ולא תוצג שוב
4. אם מורה שכח את הסיסמה, לחץ "איפוס סיסמה" וקבע חדשה

### יצירת תלמידים (מורה)

**ידנית:**
1. היכנס כמורה
2. מלא קוד תלמיד (3 תווים לפחות), שם ויתרה התחלתית
3. לחץ "צור תלמיד"

**בקישור הרשמה:**
1. בכרטיס "קישור הרשמה" הזן כמה תלמידים יוכלו להירשם (למשל 26) ולחץ "צור קישור"
2. העתק את הקישור ושלח לתלמידים
3. כל תלמיד ממלא שם מלא ובוחר לעצמו קוד אישי, ומצטרף לכיתה עם יתרה 0
4. כשהמכסה מתמלאת הקישור ננעל אוטומטית ומופיעה למורה התראה בראש המסך, שאפשר לסגור
5. "מחק" על קישור מבטל אותו מיידית. תלמידים שכבר נרשמו נשארים בכיתה

הקישור מכיל טוקן אקראי של 128 ביט, ולכן אי אפשר לנחש אותו. הוא הנתיב היחיד במערכת שכותב למסד ללא התחברות, ולכן מוגבל ל-30 בקשות ל-15 דקות לכל כתובת IP.

### ניהול החנות (מורים)
1. לחץ על כפתור "ניהול חנות 🏪"
2. **טאב מוצרים**: הוסף מוצרים חדשים עם שם, מחיר ותיאור
3. **טאב בקשות ממתינות**: אשר או דחה קניות של תלמידים
4. **טאב היסטוריה**: צפה בכל הקניות שבוצעו

### קנייה בחנות (תלמידים)
1. לחץ על "🛒 עבור לחנות"
2. עיין במוצרים הזמינים
3. לחץ על "קנה עכשיו" על המוצר הרצוי
4. המתן לאישור המורה
5. בטאב "הקניות שלי" תוכל לראות את סטטוס הקנייה

### תהליך אישור קנייה
1. תלמיד מבצע בקשת קנייה
2. המורה מקבל התראה (תג אדום על טאב "בקשות ממתינות")
3. המורה בוחן את הבקשה ומאשר/דוחה
4. אם אושר - הנקודות מורדות אוטומטית מיתרת התלמיד
5. התלמיד מקבל עדכון על הסטטוס

## אבטחה

ההרשאות נאכפות **בשרת בלבד**. אין שום דגל הרשאה בצד הלקוח שאפשר לשנות מהקונסולה.

- **סשן**: התחברות מוצלחת מנפיקה JWT חתום בעוגייה `httpOnly` + `sameSite=lax`. הדפדפן לא יכול לקרוא או לזייף אותה, ותוקפה 12 שעות.
- **הזהות מהטוקן, לא מהבקשה**: `classId` ו-`studentId` נלקחים מהטוקן. מורה שישלח `classId` של כיתה אחרת יקבל 403, ותלמיד לא יכול לבקש פעולה בשם תלמיד אחר.
- **סיסמאות**: סיסמאות מורים נשמרות כ-bcrypt (12 סבבים) ולעולם לא מוחזרות מה-API — גם לא למנהל-על. סיסמאות מנהלי-על מגיעות ממשתני סביבה בלבד ולא מהקוד. הסבב הראשון אחרי העדכון ממיר אוטומטית סיסמאות ישנות שנשמרו בטקסט גלוי.
- **הגבלת ניסיונות**: 10 ניסיונות התחברות כושלים ל-15 דקות לכל כתובת IP.
- **פעולות אטומיות**: הורדת נקודות בקנייה ובתרומה לפרס מתבצעת בשאילתה מותנית אחת, כך ששני אישורים במקביל לא יורידו נקודות פעמיים.
- **קלט**: כל סכום עובר אימות שהוא מספר שלם חיובי, וכל טקסט שמגיע מהמסד עובר בריחה מתווי HTML לפני הצגה.

### מה עדיין לא מכוסה

- קוד התלמיד נשמר כטקסט גלוי במסד. זו החלטה מכוונת — המורה צריך לראות אותו כדי למסור לתלמיד. הוא מגן על יתרת נקודות, לא על מידע רגיש.
- אין CSP. כל הדפים משתמשים ב-JavaScript מוטמע, ולכן מדיניות תוכן אמיתית תדרוש הוצאה של כל הסקריפטים לקבצים נפרדים.
